# Agentic BI MVP Design: 销售异常诊断与定价执行闭环

**Date:** 2026-03-20
**Project:** agentic-bi
**Scope:** Phase 1 MVP（单场景深打穿）

## 1. 背景与目标

本设计聚焦从传统 ChatBI 向 Agentic Decision Intelligence 的最小可行跃迁：
在一个高价值、可控风险的业务场景中，打通“发现问题→给出策略→审批执行→效果回收”的闭环。

选定场景与约束：
- 场景：销售异常诊断与促销执行
- 执行端：ERP（价格策略）
- 目标：库存去化优先（在价格约束内加速周转）
- 执行模式：半自动（分级审批后下发）
- 异常触发：规则优先

## 2. 方案选择与取舍

### 2.1 备选方案

1. 单场景深打穿（推荐）
2. 平台先行（先搭通用多 Agent 平台）
3. 双场景并行（价格 + 库存同步）

### 2.2 选择结论

采用方案 1：**单场景深打穿**。

理由：
- 以最短路径形成可验证业务闭环和 ROI 证据
- 风险控制更清晰，便于审批与审计策略落地
- 为后续扩场景、扩系统提供真实运行基线

## 3. 产品边界（MVP）

MVP 仅覆盖以下闭环：

**异常发现（规则触发） → 原因归因 → 定价策略建议 → 分级审批 → ERP执行 → 效果追踪**

MVP 明确不做：
- 多场景并发编排
- 预测模型驱动的复杂自动调价
- 全自动无人审批执行
- 多外部系统联动（仅 ERP）

## 4. 系统分层架构

### 4.1 Data Foundation
- 销售、库存、毛利等基础数据汇聚
- SKU/品类/区域等关键维度聚合
- 指标口径统一（避免同名异义）

### 4.2 Semantic Layer
- 指标字典（Metric Dictionary）
- 业务术语映射（销售、去化、毛利等）
- 优先通过语义层 API 获取指标，避免 LLM 直接拼接复杂 SQL

### 4.3 Cognitive Layer
最小 Agent 编组：
- **Router Agent**：识别任务类型（问答/诊断/可执行任务）
- **Analysis Agent**：异常归因与候选策略生成
- **Action Agent**：将审批通过策略转换为 ERP API payload
- **Guardrail Checker**：执行前强制规则校验

### 4.4 Execution Layer
- 分级审批流引擎（低/中/高风险）
- ERP Connector（定价策略 API）
- 执行回执与异常处理

### 4.5 Feedback Layer
- 执行后效果回收（24h/72h）
- 去化率、销量、毛利变化评估
- 决策日志沉淀（用于后续优化）

## 5. 核心数据流与状态机

### 5.1 主流程
1. Trigger：规则引擎扫描异常指标并触发事件
2. Diagnose：Analysis Agent 生成结构化归因
3. Propose：生成 1-3 个调价候选策略
4. Risk Grade：Guardrail 风险分级
5. Approve：按风险进入自动通过或人工审批
6. Execute：Action Agent 调 ERP 下发策略
7. Observe：回收执行后关键指标
8. Learn：记录结果，形成可复盘决策日志

### 5.2 状态机定义

主状态：
`detected -> diagnosing -> proposed -> pending_approval -> approved -> executing -> executed -> observed -> closed`

失败/分支状态：
- `rejected`
- `execution_failed`

### 5.3 强制约束
- 所有写操作须具备有效审批凭证（或符合低风险自动通过规则）
- 每次执行必须携带 `idempotency_key`
- 执行失败必须可重试、可审计、不可静默

## 6. 风控、权限与审计

### 6.1 执行前硬闸（Guardrails）
- 价格上下限约束（按 SKU/品类）
- 毛利底线约束
- 生效策略冲突校验（时间窗冲突）
- 调价冷却窗口（防抖）

### 6.2 最小权限模型（RBAC）
- Analyst：查看诊断、提交建议，不可执行
- Approver：审批中高风险策略
- Operator/System：执行已批准策略并查看回执
- Admin：维护规则阈值与审批配置

所有查询与动作强制附带租户/组织上下文，确保隔离。

### 6.3 审计对象（Decision Record）
每次策略闭环需记录：
- 异常触发快照（规则、时间、指标）
- 候选策略与最终策略版本
- 审批信息（人、时间、意见）
- ERP 请求/响应快照（脱敏）
- 执行后效果评估结果

## 7. 测试与验收

### 7.1 测试策略
- 规则单测：触发、分级、边界、冷却
- 流程测试：主链路 + 拒绝/失败分支
- ERP 契约测试：字段、幂等、错误码
- 审批测试：自动通过、人工审批、越权拦截
- 历史回放测试：验证建议有效性与稳定性

### 7.2 MVP 验收指标（初版）
- 异常命中有效性达到预设阈值
- 审批通过后 ERP 执行成功率 ≥ 99%
- 闭环追踪完整率 ≥ 95%
- 试点范围内库存去化速度相对基线提升（按业务约定口径）

## 8. 里程碑（MVP）

- **M1（可诊断）**：数据口径与规则触发可用，仅输出诊断与建议
- **M2（可执行）**：分级审批 + ERP 下发打通，形成半自动闭环
- **M3（可复盘）**：效果回收与决策日志上线，支持策略复盘与迭代

## 9. 后续扩展（非 MVP 承诺）

- 从规则优先逐步升级为规则+模型混合触发
- 从单场景扩展到库存策略、客诉分发等多场景
- 从单 ERP 扩展到 CRM/供应链等多系统联动
- 引入策略排序学习与多目标优化
